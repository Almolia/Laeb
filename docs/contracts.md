# Platform Contracts (FROZEN)

> **Law for the rest of the project.** Code against this document. Do not change without a team announcement and ADR update.

## Money

Integer **minor units** everywhere. Field names end in `Minor` (`priceMinor`, `amountMinor`). **No floats.** Use `shared_kernel.money`.

- Revenue split: 70% developer / 30% platform (`split_revenue`)
- Gift message surcharge: **0.2%** of game price (`gift_message_surcharge`)
- Festival discount: 0..100 percent (`apply_discount`; 100 = free)

## JWT

- Algorithm: HS256
- Secret: `JWT_SECRET` shared via env
- Claims: `sub` (userId, UUID string), `username`, `roles` (array from `BASE_USER` / `DEVELOPER` / `SUPPORT` / `ADMIN`), `iat`, `exp`
- Issued **only** by Identity
- Validated independently by **every service** via `shared_kernel.auth` (defence in depth — Traefik does **not** validate JWT)

## Headers

| Header | Meaning |
|---|---|
| `Authorization: Bearer <jwt>` | Auth on every protected route |
| `X-Correlation-Id` | Generated by the first service if absent; propagate on every outbound call and into every event |
| `Idempotency-Key` | **Required** on every endpoint that moves money |

## Error envelope

```json
{ "error": { "code": "INSUFFICIENT_FUNDS", "message": "...", "correlationId": "..." } }
```

## Routing

`/api/v1/<service>/...` — Traefik matches the prefix and passes the full path through. FastAPI routers declare `prefix="/api/v1/<service>"`.

Ops endpoints (container healthchecks): `/health`, `/ready`, `/metrics` (no service prefix).

Gateway-routable stub health: `/api/v1/<service>/health`.

## Event catalog

Exchange `platform.events`, type `topic`, durable. Routing key = `eventName`. One durable queue per consuming service, named `q.<service>`.

| eventName | producer | payload | consumed by |
|---|---|---|---|
| `user.registered` | identity | `userId, username, email` | profile |
| `user.role_granted` | identity | `userId, role, grantedBy` | notification |
| `game.published` | catalog | `gameId, developerId, title, priceMinor` | forum, notification |
| `game.price_changed` | catalog | `gameId, priceMinor` | — |
| `order.game_purchased` | order | `orderId, gameId, buyerId, recipientId, developerId, pricePaidMinor, isGift` | profile, review, notification, achievements |
| `order.gift_sent` | order | `orderId, gameId, senderId, recipientId, message` | notification |
| `order.refund_issued` | order | `orderId, gameId, userId, amountMinor` | profile, review, notification |
| `trade.matched` | trading | `tradeId, itemId, buyerId, sellerId, priceMinor, quantity` | wallet |
| `trade.payment_settled` | wallet | `tradeId, ok, reason` | trading |
| `trade.settled` | trading | `tradeId, itemId, buyerId, sellerId, priceMinor, quantity` | notification, achievements |
| `item.granted` | trading | `itemId, gameId, userId, quantity` | notification |
| `forum.post_stats_changed` | forum | `postId, authorId, gameId, title, reactionCount, commentCount` | profile, achievements |
| `festival.started` | festival | `festivalId, entries:[{gameId, discountPercent}], startsAt, endsAt` | catalog, notification |
| `festival.ended` | festival | `festivalId` | catalog |
| `wallet.topped_up` | wallet | `userId, amountMinor, source` | notification |

## Inter-service calls (Phase 2)

REST + JSON internally (ADR-04). Sync boundaries unchanged from Phase 1:

- Order → Catalog: `GET` effective price
- Order → Wallet: debit/credit with `Idempotency-Key`

## Database-per-service (ADR-02)

One Postgres container; one database + user per relational service (`identity`, `profile`, `catalog`, `orders`, `wallet`, `trading`, `festival`). MongoDB databases: `review`, `forum`, `notification`. No shared schemas, no cross-database joins.
